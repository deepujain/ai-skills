# Leaflet sweep and replenishment

## Playbook

Contribution queue: Maintain, Learn, Replenish

## Done means

- [x] Every authored open Leaflet PR has current branch, CI, review, conflict,
  signature, and publication evidence.
- [x] Every safe contributor-actionable finding is fixed, validated, signed,
  pushed, and answered on its exact review thread.
- [x] The bounded learning scan is complete and any durable lesson is recorded
  at the narrowest correct layer.
- [x] The queue contains five healthy, independently validated open PRs, or
  every missing slot has a source-backed blocker.
- [x] The final state is refreshed after the last mutation and recorded in the
  executable graph and this receipt.

## Constraints to preserve

- [x] Preserve unrelated user changes in the dirty Skippy worktree.
- [x] Keep Leaflet fixes narrow and isolated by PR worktree and branch.
- [x] Do not treat a maintainer-only workflow gate as a green check or a
  queue-wide blocker.
- [x] Publish no GitHub prose containing U+2014.
- [x] Preserve verified SSH signatures and Signed-off-by trailers on every
  authored commit.

## Task list

- [x] Read the relevant Skippy principles, contribution protocols, queue and PR
  maintenance playbooks, Leaflet project skill, queue policy, and learning log.
- [x] Maintain: reconcile departed contributions and inspect every authored
  open PR for current reviews, bots, CI, conflicts, branch freshness,
  signatures, and linked issue state.
- [x] Maintain: complete every safe contributor-actionable repair, focused and
  proportional validation, signed commit, push, exact-thread reply, and final
  remote re-read.
- [x] Learn: scan current review and CI outcomes plus a bounded peer/departed
  sample; classify evidence and update only durable project guidance.
- [x] Replenish: refresh live contribution policy and count healthy PRs against
  target five.
- [x] Replenish: for each missing slot, screen issue discussion, linked work,
  open and merged overlap, current source, and focused proof; publish each
  qualified contribution end to end.
- [x] Verify: inspect diffs, tests, signatures, CI, reviews, freshness, and
  exact queue count at the real local and GitHub boundaries.
- [x] Deliver: append the required summary table, complete the graph, and record
  exact external gates and resume state.

## Decision principles

- **Finish the delivery loop:** current GitHub state, not the prior bootstrap
  receipt, decides whether each PR is healthy.
- **Treat evidence as a ladder:** local tests prove behavior; GitHub checks,
  reviews, signatures, and merge state prove remote delivery health.
- **Change the smallest owning boundary:** accepted review repairs stay inside
  the affected PR and avoid opportunistic cleanup.
- **Turn lessons into leverage:** only repeated or authoritative Leaflet-specific
  outcomes change the adapter or learning log.
