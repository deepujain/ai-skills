# Leaflet sweep and replenishment

## Playbook

Contribution queue: Maintain, Learn, Replenish

## Done means

- [x] Every authored Leaflet PR has current branch, review, bot, CI, conflict,
  signature, and publication evidence.
- [x] Every safe contributor-actionable item is repaired, validated, signed,
  pushed, and answered on its exact thread.
- [x] Maintain, Learn, and Replenish are complete in order.
- [x] Five healthy open PRs exist, or every missing slot has a source-backed
  blocker or paced continuation after complete candidate screening. Public
  replenishment must obey the rolling 24-hour cadence.
- [x] Volatile state is refreshed after the last mutation and the graph reaches
  a truthful terminal state.

## Constraints to preserve

- [x] Preserve the unrelated untracked SkillSpector receipt in Skippy.
- [x] Keep each Leaflet PR isolated to its existing worktree and branch.
- [x] Treat workflow approval gates as neither test failures nor green CI.
- [x] Preserve signed and signed-off authored history.
- [x] Publish no GitHub prose containing U+2014.
- [x] Publish at most one new Leaflet PR in any rolling 24-hour window by
  default; a new sweep does not reset the window.

## Task list

- [x] Read Skippy, the contribution queue and maintenance playbooks, shared
  protocols, the Leaflet adapter, queue policy, and latest learning log.
- [x] Maintain: reconcile departed contributions and inspect every authored
  open PR for reviews, bots, comments, CI, conflicts, freshness, signatures,
  and linked issue state.
- [x] Maintain: complete all contributor-actionable repairs and exact-thread
  responses, with focused and proportional validation before any push.
- [x] Learn: inspect current outcomes and a bounded relevant peer/departed
  sample; adopt only durable source-backed lessons.
- [x] Learn: correct the durable burst-publication and repeated-description
  failure in the shared skill, Leaflet adapter, playbooks, and scheduler prompts.
- [x] Replenish: refresh live policy and healthy count; fill each missing slot
  through issue, overlap, current-source, regression, validation, signing, and
  publication gates. No slot is missing at 5/5 healthy open PRs.
- [x] Verify local diffs and real GitHub delivery state.
- [x] Append the required summary table, refresh volatile claims, and complete
  the executable graph.

## Decision principles

- **Finish the delivery loop:** current GitHub state controls every PR health
  claim and replenishment decision.
- **Treat evidence as a ladder:** local proof and GitHub delivery state are
  separate gates.
- **Change the smallest owning boundary:** any repair stays within the PR whose
  current head owns the finding.
- **Turn lessons into leverage:** only recurring or authoritative Leaflet
  evidence changes the adapter or learning log.
